# 社区学习与聊天定向评估

执行 `node scripts/evaluate-community-chat.mjs --output=.tmp/community-chat-evaluation-日期`，使用当前社区库的一致性快照、当前角色卡和 26 个合成 QQ 场景。不会采集 B 站、发送 QQ、添加生产知识，也不会为每轮聊天调用检索模型。

加 `--real` 才调用当前正常聊天所选模型，最多三对、六次，每次输出最多 256 Token、额外费用上界 0.05 元，同时受现有每日和会话预算约束。固定 `temperature=0.3`，两组同角色、同历史、同输入；只切换社区知识。模型未提供可信 usage 时保留未知用量与预算预留。凭据和原始推理不写入结果。

离线报告只测检索和提示选择，不能声称机器人已使用知识。真实回复记录字面出现及供应商 usage；正确释义、适用性、自然度、任务完成情况需人工复核，不能用字面出现代替语义正确率。`results.json` 保留各项分子分母，`report.md` 提供对照案例。快照只保留在本机忽略目录，不能上传包含原始证据的运行数据。

聊天内复用现有 SQLite FTS 与原生已确认黑话，统一由 StyleResolver 选择。普通知识最多三条，主动表达最多两条并受共同提示预算约束；不强制使用，不设置额外的争议词条类别黑名单。明确求助、技术讲解、收尾和明确拒绝玩梗仍按用户原意处理。会话状态保存最近推荐的知识指纹、时间和聚合计数；不同群隔离，重启后保留短时重复抑制。

统计分别记录命中、选中、请求接受后的注入、成功 QQ 发送、回复中字面出现；语义使用未能确认的保持未知。日志写入现有 `logs/bridge/learning/*.jsonl`，社区采集与验证继续写入 SQLite 和 `logs/bridge/community-learning/*.jsonl`；不另建知识库或保存原始聊天到统计中。
