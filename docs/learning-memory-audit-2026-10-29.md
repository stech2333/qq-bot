## 为什么部分学习没有产生成果

1. 自动话题/黑话/风格研究今日已使用 30/30 次额度；目前不是空闲即继续无限调用。配额会阻止后续请求。本次保留原额度与账目，没有提高上限。
2. 全局风格当前合格样本约 184 条，覆盖 2 天、13 位发言者、2 个群；要求至少 20 条、3 天、2 位发言者。日期门槛尚未满足，之后还需要稳定轮次和新增语料，不能立即发布。没有降低门槛。
3. 原黑话 58 条均缺少满足当前规则的公开来源验证与一般化释义；49 条仍等待语料研究确认，48 条缺少释义，另有真人数量、参与人数、使用时间跨度和评分不足等重叠原因。没有把候选强行改为 confirmed。
4. 长期事实依靠聊天模型调用带真实 sourceMessageId 的记忆工具写入，或管理员明确保存；仅收到聊天消息不会自动把每句话变成长期事实。后台自动研究主要处理话题、黑话和风格，并非全量事实摘要器。
5. 社区的 122 条待验证候选不能当作已发布知识使用，后续仍需证据和复核；当前持续学习为 STOPPED。本次没有重新开始学习。

原黑话模块的公开网页释义检查还包含关键词重合启发式，不能单独视为完整语义证明；它同时依赖模型审核、真实群聊来源、多人和时间门槛。本次记录此局限，没有扩展修改原黑话的语义判定策略。

## 学习日志保存补齐

统一事件日志已接入并通过管理接口确认成功落盘：

```text
D:\Projects\BigFatFish-QQBot\integrations\qq-bridge\logs\bridge\learning\YYYY-MM-DD.jsonl
```

文件按北京时间日期分开，单卷达到 10 MiB 后写入同日 `.1.jsonl`、`.2.jsonl` 等分卷；不自动删除旧卷。磁盘或权限导致写入失败时，管理状态中的 `learningLog.ok` 会变为 false，并给出错误提示，不能把失败写入报告成保存成功。

记录范围：系统启动、原始样本落盘、话题/兴趣证据变化、记忆保存与回滚失败、自动研究额度占用与额度阻塞、审核通过/拒绝/失败、风格累计与发布、黑话词库保存及自动确认、手动研究进度、情绪判断保存结果。

日志采用字段白名单，只允许时间、随机事件 ID、模块、事件、散列会话标识、任务 ID、状态、规则代码和有限计数。不会复制原始聊天、私人事实、提示词、完整模型输出、字幕、引文、Cookie 或 API Key；未提供的字段不写 null。

“OBSERVED”表示发现候选或证据；“PERSISTED”表示主状态已经保存成功；额度占用日志不代表产生了知识。主数据落盘失败会回滚并记录失败，事件日志本身失败不会伪造知识写入成功，也不会抹掉已保存主数据。
