# 南航聊天与社区独立模型路由

## 管理页面

聊天、话题、风格与黑话研究继续通过“模型与 API 池”选择接口。社区页面新增“社区学习模型”，可选择跟随聊天、原 DeepSeek 接口，或单独指定已保存的 DeepSeek Chat Completions 条目。

独立路由保存在 `communityLearning.modelRoute`，固定选择接口后不受聊天切换影响。指定条目丢失、停用、缺少凭据或协议不兼容时，社区模型拒绝调用，不会静默改走其他接口。正在被社区使用的条目不能直接删除、停用或改成不兼容协议。改社区路由会取消现有学习任务，后续使用新设置。

## 无代理与校园 DNS

南航域名同时返回校园内网 IPv4 `10.0.241.133` 与公网 IPv6 `2001:da8:1006:1001::101`。本机已验证公网 IPv6 可直连，因此不需要任何私网例外。

- 仅南航模型域名支持从混合 DNS 中选择公网地址，私网答案全部丢弃；只剩内网、环回、元数据或非法地址时立即拒绝。
- 连接使用校验后的地址，保留原域名的 Host/SNI，继续验证 TLS 证书，不发生第二次未经检查的 DNS 解析。
- 聊天服务的启动模块为南航标准 HTTPS 模型列表与 Chat Completions 操作指定直连 dispatcher，禁止跟随重定向。它使用同一版本 undici 的 fetch 与 Agent，避免 Node 内置 fetch 的 dispatcher ABI 差异。
- 社区仍使用无代理的原生 HTTPS 请求，不注册工具，不传 QQ 身份、聊天历史、私人记忆或系统管理权限；上游返回工具请求会被拒绝。
- QQ 网页抓取继续使用更严格的原规则，不共享校园 DNS 特例；其他模型域名、网页和服务的网络设置保持原策略。

ServiceManager 自动为 DSH、桥接服务增加 `model-network-preload.mjs` 启动模块。已运行的旧版管理器通过本项目 `.env` 的同一 NODE_OPTIONS 加载项兼容部署；不会改用户级代理或关闭系统代理。搬迁仓库后应使用更新后的管理入口，并检查本地 NODE_OPTIONS 中的旧路径。

## 验证

相关后端回归 118 项通过；社区页面测试包含独立接口保存、聊天路由保持不变、草稿、桌面/移动端布局与既有开始/停止等操作。额外验证了聊天 fetch 在不可用代理配置下依然直连南航，无密钥访问模型列表正确返回 401。修改后的社区客户端真实请求返回有效 JSON，推理 Token 为 0，没有调用工具或写入学习知识。

模型链路验证只使用最小合成请求，不等同于已运行实际社区采集和持续学习。
