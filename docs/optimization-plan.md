# BigFatFish 统一优化方案

日期：2026-10-27。状态：方案待实施。本次源码发布不表示已实施以下整改，也不触发运行测试、模型调用或 QQ 消息发送。后续修改与测试分别按管理员明确指示进行。

## 1. 最终架构与范围

只保留一套生产系统：**QQ ↔ SnowLuma ↔ QQ Bridge ↔ DeepSeek Harness（DSH）↔ API 模型**。继续使用现有启动管理与 QQ Bridge 控制台。

参考 local_qq 中 AstrBot 的人格注入、上下文压缩、工具链完整性及中文检索设计，在现有 JavaScript 项目中实现。避免再引入另一套生产消息处理器和 Python 运行链路。

保留已有功能：分会话人格、群聊/私聊启用名单、正式回答、话题学习、全局风格、共享黑话、长期记忆、心情、主动聊天、QQ 收藏表情、独立语音接口、API 池和管理页。聊天生成继续使用 API，本地仅处理规则、索引、检索和统计。

## 2. 已核对的问题与事实

| 项目 | 当前观察 | 整改方向 |
| --- | --- | --- |
| 人格卡 | 普通唤醒正文带完整人格卡，5,355 字符、13,779 UTF-8 字节 | 迁入会话作用域系统提示，保留原文供管理 |
| 仿真预设 | 系统前缀为9,067字符、21,429 UTF-8字节 | 精简重复内容，保留权限和工具契约 |
| 普通唤醒 | 隔离构造约10,205字符，不含收藏表情资料 | 改成精简的本轮动态包 |
| 重复行为规则 | 卡片之外闲聊规则出现两次，分条偏好出现四次 | 统一组装与单一注入入口 |
| 用量统计 | 已有 token、缓存命中及费用账本 | 扩展用途和提示组成归因 |
| 记忆 | 已有按会话的来源校验、更新、失效与相关性检索 | 增强检索，避免重复建设 |
| 消息上下文 | 已配置最多12条唤醒未读和4条近期消息 | 按预算处理，不能等同于每次固定注入20条 |

这些数字是 JavaScript 字符长度与 UTF-8字节数，不能当作供应商 token 数。测量使用一条合成群消息、关闭表情上下文，不代表所有真实请求。历史中保留多少旧唤醒取决于 DSH 会话及压缩过程，不能直接按20份人格卡计算实际费用。

## 3. 统一提示词组装

引入一个提示词组装器，正常回复、主动聊天和工具查询共用结构化结果。

```text
稳定系统部分：工具与权限规则 → 当前人格核心 → 已发布全局风格 → 少量角色示例
历史部分：较早摘要 → 最近完整对话和完整工具调用链
本轮动态部分：待处理消息、回复对象、唤醒原因、时间、相关资料与必要运行信息
```

- `instruction()`、`responseContext()`、`buildWakePromptV2()`不再各自重复拼接规则。
- 普通聊天、正式回答、主动发言仅保留场景差异；人格、风格、分条、记忆各有一个注入入口。
- 人格模板原文不删减；人工整理精简核心、角色示例和背景资料，背景按需检索。
- 时间、令牌、消息水位、临时状态置于动态部分，避免污染稳定前缀。
- DSH 本机安装版本支持作用域化系统提示。按会话绑定人格，不能改写所有群共享的部署前缀。
- 不以“首次 bootstrap 注入后永不再管”代替稳定系统提示，防止压缩后丢失人格。
- 人格切换沿用会话退役、旧令牌撤销及新会话机制，保留本会话长期记忆；旧人格结果禁止发送。
- 保留预设安全硬性不变量及服务器端权限检查，不能用缩短提示词代替实际鉴权。

DeepSeek 缓存依据前缀复用，不只对 system 消息有效。稳定前缀有利于复用，但缓存是尽力而为，不承诺命中率。[官方说明](https://api-docs.deepseek.com/guides/kv_cache/)

## 4. 风格学习与表达示例

保留当前八类有界特征作为可控边界，增加表达统计与场景示例。

- 统计常见句长、标点、分条、口语表达，仅作参考，不强制固定长度或条数。
- 示例保存“场景—表达”，覆盖同意、不同意、接梗、解释和结束话题。每轮最多检索两条相关示例。
- 全局表达风格共享；人格示例归人格；真人原始消息、事实和话题按群/私聊隔离；当前群的表达参考只用于该群。
- 私聊原句不自动进入全局示例。全局示例只接纳管理员确认、去身份化、无私人事实的材料。
- 机器人输出不能未经审核反复用于学习。优质回复进入示例须有人工确认或可靠的明确反馈。
- 示例作为资料而非指令，检查来源和隐私，防止把聊天中的命令升级为系统规则。
- 沿用版本、来源失效、锁定、人工覆盖、删除截止时间和回滚机制，增加版本名称、修改摘要和示例差异。
- 六小时是最短分析间隔；仅有有效内容变化时发布新版本，不为更新时间戳空发版本。

相关示例检索值得采用，但非正式个人风格仍有模仿局限，不能承诺完全消除“AI味”。[示例选择研究](https://aclanthology.org/2022.deelio-1.10/)、[风格模仿研究](https://arxiv.org/abs/2509.14543)

## 5. 记忆、话题与共享黑话检索

统一检索入口，独立维护资料范围。先过滤权限、会话、来源、有效期、删除状态，再排名。

建议一轮资料上限：长期事实3条、相关话题2条、表达示例2条、已确认黑话通常3至5条，必要时补短摘要。所有条目共同受提示预算限制。

- 复用现有中文分词，增加 BM25 排序、索引版本和失效更新；首版不引入向量数据库或本地模型。
- 长期事实保留人物归属、记录时间、来源及新旧替代关系。用户纠正或删除后，旧事实不得从摘要或索引复活。
- 未确认兴趣和黑话候选不能作为事实知识注入；候选达标后仍经过研究和确认。
- 黑话全局共享释义与通用用法，私聊语料不进入共享研究。检索同时考虑词名、含义、使用场景和已确认别名，减少单纯按热度选词。
- 模型根据语义选择是否使用黑话，不规定每条回复用词，不机械替换原话。
- 存储窗口、学习窗口、提示窗口分开。保留现有学习记录与近期存储，只减少本轮展示量，不直接把 recentLimit 从100降到20。
- 摘要携带来源、时间和人物，不能把未展示的待回复消息用摘要替代后自动确认处理。

长期记忆需要覆盖事实更新、时间推理和无依据时保留判断，而不只是关键词命中。[LongMemEval](https://arxiv.org/abs/2410.10813)

## 6. 正常回复与主动发言

保持当前策略：普通旁观40%，已参与话题60%，兴趣话题60%，上下文随机主动18%；明确称呼、真实@和私聊沿用原规则。

18%仅在普通回复未选中且满足条件时作为补充机会，每批消息只抽一次。它不是总发言概率。额度为上限，不是必须完成的发送量。

主动发言须有具体切入点：本群仍在讨论的内容、相关未表达观点、有来源且有效的待说想法，或明确约定的后续事项。没有切入点就结束机会。定时器只检查，不制造必发任务；删除“没话就搜热点、大胆开口”等推动无关发言的规则。

优先级统一为：**明确待答 → 正常接话 → 上下文主动 → 冷场主动**。各类任务共用调度器和发送链，不新增独立主动发送队列。

主动生成中出现直接提问时，撤销旧主动任务并安排正常回复。旧生成稍后返回也不能发送或确认新消息。发送前复查会话启用、人格版本、任务有效期、消息水位、静默时间和配额。

## 7. 消息生命周期与防重复约束

明确区分待处理、本轮已展示、已处理、已发送和发送结果未知。读取不等于回答，处理游标不等于每条都已回复。

必须保持：

1. 只有本轮实际展示过的范围才能被本轮确认；生成和发送期间的新消息继续等待。
2. 正常回复优先于主动机会；被撤销的旧任务不重放。
3. 多条消息部分成功时只记录成功部分，不整轮重发。
4. QQ已接受、随后本地记账失败不能导致再次发送。
5. 超时但无法确定结果时进入未知状态，通过可用回执核对，不盲目重试。
6. 人格切换、权限收回、会话停用及任务过期后禁止旧结果发送。
7. 文本、收藏表情和独立语音共用发送顺序。

OneBot 与本地数据库之间没有统一事务，不能承诺严格全链路 exactly-once。通过任务编号、回执、去重记录和未知状态处理降低重复风险。

## 8. 模型、预算和表达检查

首版保留现有 DeepSeek 官方接口与 deepseek-flash；API池继续人工切换。普通闲聊拟采用low，复杂解释与工具任务采用high。

启用档位分流前必须解决 DSH selectModel 同时修改全局默认值的副作用，确认选择仅影响目标会话或目标回合；未完成前保留当前设置。low不等于关闭思考，各协议按实际能力映射，不传不存在的通用参数。[DeepSeek说明](https://api-docs.deepseek.com/guides/thinking_mode/)

预算统计包含系统提示、工具定义、历史、动态资料、工具返回及适用的推理回放。普通聊天以8千token软预算和12千token告警线作为设计起点，正式问题按需放宽；这些数值是待验证参数。

超预算时先减少无关资料和重复工具结果，再压缩较早完整轮次。保留当前问题、原始来源及完整工具调用/返回配对，不直接截断JSON或令牌，不删除必要推理回放。不得把120至200token的可见回复目标直接设为所有工具和推理的统一输出硬上限。

表达检查用于普通闲聊：识别明显客服套话、反复结构与机械结尾。仅高置信问题触发一次重写，失败保留原结果；正式解答允许步骤、列表和完整解释。不得仅凭“首先”“而是”等词就重写，不硬截正文，不改事实与链接。

沿用现有合批和等待节奏，不叠加第二套延迟，不故意拖延明确提问。

## 9. 后台学习与反馈

复用已有研究任务、每日额度、重试和来源校验。轻量计数与索引本地执行；只有新增足够证据才请求模型。后台分析与实时首答分开调度，正常聊天繁忙时让出执行机会。

记录可靠反馈：明确回复或引用、管理员对特定消息标记好/差、相关对话延续。不能把相邻群消息直接认定为回应，也不能把无人回复直接认定为差评。反馈先用于管理和示例候选，不自动改人格、不直接训练模型。

首版不引入云端微调、LoRA或DPO，也不将现有聊天记录自动上传为训练集。先通过提示与检索形成可解释闭环。

| 人格与角色 | 核心、示例、背景资料、各会话实际绑定版本 |
| 提示词诊断 | 组成长度、重复来源、预算与实际注入预览，隐藏令牌 |

版本回滚恢复提示、策略和示例；消息水位、发送回执与去重记录继续向前，不能回滚后重放历史。预览和诊断只对管理端开放，不暴露给QQ会话工具。

## 11. 实施顺序与交付门槛

1. 统一提示组装、删重复、人格进入会话系统提示。
2. 整合记忆、话题、黑话检索，加入有限表达示例。
3. 明确主动切入点、任务优先级及消息生命周期。
4. 处理模型档位作用域，再接入预算、表达检查和反馈。
5. 补齐管理页发布管理，只保留一个QQ生产接入与启动入口。确认后再清理冗余部分，不在整改前删除数据。

实现放在 extensions/bigfatfish 与现有桥接入口，所有接入改动同步维护 scripts/apply-bridge-extension.cjs，避免重新应用补丁时丢失。

后续获准测试时的交付门槛：不串群、不串人格、不重复发送、不吞新消息、失效记忆不复活、后台学习不阻塞首答、配置回滚不重放历史；还应覆盖重启、并发、部分发送失败、未知回执、研究旧结果回写以及工具链压缩。

零bug无法仅凭设计承诺。先按以上不变量实现，再由管理员明确授权测试与部署，逐阶段审阅和交付。

## 12. 技术参考

- [DeepSeek前缀缓存](https://api-docs.deepseek.com/guides/kv_cache/)：按稳定前缀复用，命中率尽力而为。
- [DeepSeek思考与工具调用](https://api-docs.deepseek.com/guides/thinking_mode/)：遵守实际协议、档位及回放要求。
- [AstrBot上下文压缩](https://docs.astrbot.app/en/use/context-compress.html)：参考预算和上下文管理结构。
- [AstrBot知识库](https://docs.astrbot.app/en/use/knowledge-base.html)：资料检索与人格配置分离。
- [What Makes Good In-Context Examples for GPT-3?](https://aclanthology.org/2022.deelio-1.10/)：相关示例选择的研究依据，不直接外推QQ群收益。
- [Catch Me If You Can?](https://arxiv.org/abs/2509.14543)：非正式个人风格模仿仍有局限。
- [LongMemEval](https://arxiv.org/abs/2410.10813)：记忆需评估时间、更新与无依据判断。
- [Lost in the Middle](https://arxiv.org/abs/2307.03172)：长上下文中的信息位置会影响模型利用，不能将论文结果直接当作本项目收益。

本方案未复制AstrBot实现代码；实际移植第三方代码时须保留并遵守相应许可证。上游QQ Bridge来源和许可证保留在项目对应目录。
