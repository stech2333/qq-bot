2026-10-28；基线 `2a7a89b`。按要求集中在实现结束后统一审查和测试，修复失败项后完成最终回归。未推送本次改动。

## 最终架构与边界

QQ → SnowLuma → Bridge → DSH → 现有 API 的主链路保留。管理员选择唯一全局人格；群聊共同贡献唯一全局风格；一个规范化黑话词条可包含多个语境释义。群聊、私聊各自维护上下文、事实、兴趣及心情，私聊不参与全局学习。

风格先验证真实群聊来源，去除自发消息、转发/引用、敏感文本、重复和刷屏，再按群、日期、成员轮转抽样。至少跨三日、两名成员，多轮新增证据才能自动发布；单群额外增加观察轮次且单轮只变更一项。成熟特征替换需要新的跨日证据。模型评分标为未校准支持度，不能解释为正确概率。表达仅允许枚举与有限描述语法，不保存私人原句或身份覆盖指令。

黑话以 NFKC 规范词面生成稳定 ID，同词不同含义保存为多个 sense。自动研究必须有真实来源、公开 HTTPS 页面佐证、一般化声明、隐私检查、预算及版本保护。无法验证的结果保持候选。检索先匹配当前待答消息，再选择语境释义；技术/求助场景与私聊均可检索，不注入整库。公开页面匹配是保守的辅助校验，不能保证释义绝对准确。

## 迁移和恢复

迁移在本机启动时执行，生产密钥和聊天数据不进入源码。现有会话、映射、人格状态、旧设置、词库和旧风格文件先保留 `.pre-v3.bak`；DSH 安装器另外保留配置备份。

- 旧群风格转为待重新验证的安全候选，不拼接为全局提示词；原文件备份保留。
- 旧词库按规范词面合并，相同义项去重，不同义项保留。原 scope/ID 存入迁移信息，来源不足或私人词义不全局发布。
- 旧会话事实仍属于原会话。来源删除记录独立持久化，清理/恢复时继续尊重删除记录；删除黑话可从控制台恢复为需重验的候选。
- 旧人格绑定原文件备份并留作档案，正式解析只使用全局人格。
- 新心情默认开启；已有明确或无法区分来源的 `enabled:false` 保留关闭，并记录迁移来源。
- `chat`、`reserved`、未知模式保持安全关闭，不因升级启用主动发言。已有 `reserved2` 保留。
- 损坏文件或迁移失败停止覆盖。需要整机回退时先停止桥接/DSH，再恢复匹配版本的源码与本机备份；不要删除来源/词条删除记录来强行恢复已撤销内容。风格版本可在 UI 回滚，回滚后锁定，解除锁定才恢复学习。
