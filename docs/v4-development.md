# BigFatFish V4 开发与使用说明

现行持续学习配置请使用 [V4.1使用说明](v4.1-community.md)。本文保留V4历史基线；其中每日次数/固定深读条数、Schema v2、完整快照每秒轮询和仅文件/Feed的描述已由V4.1替代。

基线：2026-10-28 同步 `origin/main`，提交 `5e6a4210443562c921249c11e18683c51955db48`。本地工作分支：`codex/v4-community-learning`。本次不部署，不连接真实社区或发送真实 QQ 消息。

## 审查结论与最小修改范围

已审查 `runtime`、MemoryManager、memory-recall/history、LearningWindow/Research/Sources、GlobalStyle/StyleLearning/Resolver、ExpressionMemory/Retrieval、SlangManager、InterestMemory、DiscussionTopics、Mood、Participation、DeliveryLedger，以及 Bridge 的消息接收、角色注入、会话恢复、唤醒组装、发送确认、模型选择和管理端鉴权入口。现有 W/E/F/P、角色签名和发送协议继续复用。

确认的缺陷及局部修复：

- 正式风格/黑话在引用样本离开短期窗口后失效。候选仍需窗口内原文验证；已正式发布的结果改为检查保存的来源证明、会话许可和删除墓碑，不再要求原始短期样本永远存在。
- 删除单条来源时原代码清空全部摘要、活跃话题、待说事项和人物印象。改为按来源关联清理；有其他独立确认的事实保留；不明来源的旧资料不推断为依赖此来源。
- LearningWindow 原来直接拒绝私聊。现在按已允许的会话保存私聊独立窗口；全局 LearningSources、风格研究及黑话候选仍只接收群聊许可语料。
- 群友明确 @ 其他人且正文提及机器人名字时，原普通参与路径仍会将其视为必须回应。现按其他目标降低参与优先级；真实 @ 机器人及引用机器人仍直接回应。

社区学习补充四个模块，没有改造普通聊天框架。`bridge.js` 仅增加模型连接及后台 tick；可复现接入保存在 `scripts/v4-bridge-patch.cjs`。没有新增主导航。

## 社区来源与授权

目前 **没有内置或实际验证任何平台爬虫/登录读取器**。B站、贴吧、知乎、小黑盒、虎扑均默认未接入。五个平台复用统一只读适配器：

1. `authorized-file`：管理员放在桥接 `state/community-imports/` 中的自有或获授权 JSON 材料，拒绝路径穿越和符号链接。
2. `authorized-feed`：已获授权的 HTTPS JSON Feed，复用 `safe-fetch.js` 的 DNS/IP/重定向保护、大小限制，并新增可选 AbortSignal。拒绝含凭据和查询串的 Feed 地址。

两类适配器均需来源级读取、持久保存、AI学习三项授权及依据。没有授权时绝不进行发现或读取。单凭项目开源许可证、网页公开或拥有登录 Cookie，不视为材料学习许可。

材料格式（下面是虚构示例，不能冒充实际采集结果）：

```json
{
  "version": 1,
  "items": [{
    "id": "example1",
    "title": "游戏文化：示例词条",
    "summary": "与配置主题相关的简短摘要",
    "text": "包含词条和可核对释义的获授权原文。",
    "url": "https://www.bilibili.com/video/BVexample",
    "publishedAt": 1793100000000
  }]
}
```

文件最多512KB、1000条；文本每条最多16000字，模型只看最多2400字正文。链接需是相应平台的无查询参数 HTTPS 链接，不接受任意来源伪装平台。当前不支持分页协议、Cookie管理、视频下载、验证码处理或平台互动。Feed由提供方负责授权和增量内容，程序只做GET。

来源被停用、读取/学习许可撤回或过期后停止读取和应用对应证据。保存许可撤回或许可到期会清理其证据、候选和处理指纹；无其他来源支撑的知识清空正文并保留撤销墓碑。独立备份及外部授权材料文件需管理员按相应许可管理保留期，程序不会擅自删除管理员原文件。

## 模型隔离与低Token处理

社区模型采用独立 Chat Completions 请求，不创建 QQ Agent 会话，不加载 QQ preset，不挂工具，不传 QQ历史/私聊记忆，不读取网页指令指定的本地文件。普通聊天仍由 DSH 和原 API 池生成。

优先读取当前 API 池的 DeepSeek Chat Completions 模型元数据；凭据先使用匹配的环境变量 `QQ_POOL_<条目ID大写>`，否则复用现有`readDshCredential()`只读取DSH凭据文件中的**同一个命名ref**。未使用 API 池时读取`DEEPSEEK_API_KEY`的环境值或DSH同名ref，以及原DeepSeek模型ID。不会遍历其他凭据、导出到环境或显示Key；无需为学习重复填写已保存在当前DSH模型配置中的凭据。两处均没有对应Key时明确暂停，原聊天不受影响。

费率上界必须配置，单位人民币/百万Token；不猜测校园或代理接口费用。每次模型请求前按完整系统文本、输入 UTF-8 字节数及安全余量预留输入上界，预留完整 `max_tokens` 输出上限和费用。该预留不是实际Token计数。收到有效usage后结算；失败、取消、未知usage均保留预留，不返还不确定支出。费用按管理员费率上界计算，不冒充实际账单；推理Token是输出的子集，不重复计费，缓存命中仍按输入上界计价。

模型请求使用流式响应及`stream_options.include_usage`。页面每秒获取快照，分别显示今日/本轮实际已确认输入、输出、推理及缓存命中；在途预算预留；在途输出/推理估算。服务端提供usage帧时立即更新实际值；仅有文本片段时按UTF-8字节数/4估算并明确标注，不能当作真实Token。流式更新最多每500ms持久化一次，实际usage到达时立即保存；预算仍保持预留直到有效结果结算。只统计推理片段字节数，不保留原始推理内容。响应截断或工具请求会拒绝发布，但已收到的实际usage仍可展示。

流程：本地发现元数据 → 指纹去重/授权/主题筛选 → 一次模型选择（最多2/4条）→ 顺序读取选中片段 → 一次批量结构化提取 → 本地Schema/隐私/原文引用及释义支撑检查 → 黑话、多义或冲突再批量复核 → SQLite事务发布。没有每条评论一次调用，没有无边界探索。表达策略只允许现有 `STRATEGIES` 枚举，不发布自由文本系统指令。

默认：并发1、来源并发1、每批8条、每日最多8个模型研究任务、输入48000/输出16000/总64000Token、每日费用上界2元、单次输出1600Token、单任务180秒。初始值未经生产压测。`low`提取、`high`冲突复核按 DeepSeek Chat Completions 协议传递；不调用可能修改 DSH全局默认值的 `session.selectModel`。API池在任务中途改变时暂停本任务。学习在正常QQ会话忙时让出后续调用，已在途网络请求独立运行，不占QQ发送队列。

协议依据：[DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)。没有永久保存模型原始推理内容。

## 任务、数据库与恢复

状态包括 OFF、IDLE、DISCOVERING、FETCHING、FILTERING、EXTRACTING、VALIDATING、PUBLISHING、PAUSED、CANCELLING、CANCELLED、FAILED。完成时数据库用`COMPLETED`释放活动任务唯一约束，页面显示IDLE（完成）。任务保存UUID、状态版本、来源版本、generation、进度、预算调用次数、期限和错误。

全局设置变化、来源修改、取消和知识撤销使generation失效，并尝试中断在途请求。即使对方忽略取消，旧结果也不能通过发布事务的再次检查。单实例内不创建排队任务，运行期间的再次启动合并到当前任务；数据库唯一索引也防止两个实例同时发布活动任务。进程失活或任务期限过后，重启把未完成任务标为PAUSED，下次从未提交指纹增量重新执行，不重用不确定模型返回。

`state/community.sqlite` 是社区 K 的唯一可写权威。内置 `node:sqlite`，部署推荐 Node24（当前环境24.20.0）；缺少SQLite/FTS5、损坏或未来Schema时仅暂停社区功能，不影响基本聊天。Schema v2 包括来源/许可、任务、文档指纹、候选、知识、证据、版本发布/撤销记录、预算usage、FTS5索引和学习日志。采用 WAL、外键、短事务、100ms busy timeout、活动任务唯一约束。已有未知v0数据库及v1升级前通过`VACUUM INTO`备份，未来版本拒绝写入。v1→v2只新增日志表/索引，原知识和usage保持兼容；没有搬迁QQ聊天JSON，也没有把同一正式知识同时写入SQLite与黑话JSON。

已有SlangManager仍管理QQ群来源的正式黑话，GlobalStyle仍管理一套全局风格。社区梗/黑话/知识/受限枚举策略通过社区K的业务发布接口和现有记忆装配接口提供，不复制到旧JSON形成双权威。检索会实时检查来源状态、许可和发布状态；撤销后该知识ID不被旧材料重新激活。新证据为同条知识追加证据/版本；不同语境保留独立词义。

管理页“备份知识库”生成一致SQLite快照。恢复：停止桥接，保留当前数据库和相关WAL/SHM作故障快照，再将选定备份复制为`community.sqlite`，不得混用旧WAL/SHM；重启前复核来源许可。回退旧程序时保留独立社区库，旧QQ状态不需要逆迁移。恢复历史备份不能撤销真实外部许可收回，应先重新登记有效许可再启用。

## W/E/F/K/P与本地RAG

- W：原近期消息、未读水位、引用、待答批次与会话状态保持原实现。
- E/F：原`facts.kind=event|stable`和MemoryManager版本/替代/删除接口继续使用。存来源消息、成员、记录时间；新增来源时间输出、上海时区今天/昨天/前天过滤。成员第一人称查询仍按来源成员限制。
- K：SQLite正式社区知识，所有允许会话共享，不在聊天时联网。
- P：原一套全局GlobalStyle；私聊不进入全局样本。社区策略作为有限枚举资料进入K，不替换正式全局人格或风格。

当前待答/明确找机器人的消息优先生成检索查询；私有事实从**当前会话状态**开始检索，不会全局查询后再过滤。公共知识使用精确词条/中文分词和二字片段 + FTS5/BM25；按语境词选择多义词，校验来源许可/发布状态、去重和字数预算，默认最多4项1200字符。没有命中就不注入；阶段摘要只在历史类查询时加入。数据库故障回退会话上下文，不编造来源。未引入Embedding或向量服务。

时间检索目前覆盖明确相对日和既有来源时间；没有另建事件知识图谱、自动推断复杂人物关系或所有自然语言时间表达。旧无来源派生资料无法可靠追踪，不因删除任意消息而全清；可由管理员逐条清理。

## 管理端与普通回复

社区控件在“记忆与学习→长期记忆”内部。支持总开关、独立知识应用开关、五个平台、主题/强度、各项预算、授权来源/到期、手动启动、取消、状态/错误/进度/新增数、最近任务、知识撤销、数据库备份。仍然六个主入口。

“开始学习”自动保存当前主题、平台和预算草稿，再检查平台、主题、许可来源、文件是否存在、模型凭据、费率和每日额度。条件缺失返回`NOT_READY`、完整缺失清单和日志，不谎报启动成功，也不会创建任务或调用模型；条件具备后持久开启调度并立即尝试首轮。QQ繁忙时明确记录等待并在后续tick恢复。“结束学习”持久关闭总开关、取消当前任务、阻断晚到发布；不影响已发布知识的独立应用开关。“仅学习一次”保留已有单轮入口；“取消当前任务”不关闭后续调度。

日志记录启动检查、配置/开关变化、任务创建、阶段切换、筛选数量、模型请求/预算预留、实际usage、发布数量、取消和失败原因。SQLite最多保留2000条，页面显示最近100条并每秒刷新。没有记录模型原始推理、QQ私人记忆、API Key或完整外部正文。存储不可用时仅在内存提供临时日志，并明确不保证重启后保留。

更新静态页面后，已经运行的旧Bridge进程不会自动重新加载JavaScript模块。若该进程尚不支持社区API，页面在社区区域显示“重启 QQ Bridge 后刷新”的明确提示，停用该区域写操作并停止自动轮询，保留长期记忆读写。启动管理页重启Bridge后，可点“刷新学习状态”恢复社区控件。更新源码或生成页面本身不会替管理员重启生产服务。

沿用Bridge全局控制台令牌、CSRF检查和管理员路由；带agent标志或agent token的社区API被拒绝。没有QQ聊天控制社区学习的命令。外部内容用textContent展示。

回复仍按原链路：接收/身份和去重 → 真实@和引用/参与决策 → 原会话隔离检索 + 公共K → 既有StyleResolver/角色系统装配 → DSH生成 → 原QQ工具、权限白名单和发送保护 → OneBot实际回执 → DeliveryLedger/已发送水位/后续记忆及心情。生成文本不算发送。原ACK、部分失败、未知投递和补救机制不重新实现。
