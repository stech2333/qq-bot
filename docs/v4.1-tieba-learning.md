# V4.1 贴吧定向学习

在“记忆与学习 → 社区持续自主学习 → 授权来源管理”点击“添加指定贴吧”，填写一个具体吧名、授权依据、有效期及读取/保存/AI学习许可。每个吧新建一个来源编号；不得把旧来源的 target 改为另一个吧。可以共享 `tieba` 本地连接器。来源登记本身不会产生 READY；启用贴吧平台后，对该来源执行“检查此来源”。

吧名先精确请求，保留真实名称中的“吧”；仅在服务端返回的规范名支持、或明确不存在且精确请求失败时尝试去掉末尾一个“吧”。网络错误不会触发名称替换。后续请求绑定真实 fid 和规范名称，不使用学习主题扩展发现范围。

管理员在实际桥接运行目录 `integrations/qq-bridge/state/community-connectors.json` 的既有对象中添加连接器（保留原有 bilibili 对象）：

```json
"tieba": {
  "platform": "tieba",
  "driver": "aiotieba",
  "command": "D:\\管理员选择的环境\\python.exe",
  "args": [],
  "minRequestMs": 2500,
  "credentialRef": "QQ_COMMUNITY_TIEBA_BDUSS"
}
```

此示例的 Python 路径必须替换为真实环境。如果合法公开读取无需凭据，可省略 credentialRef；如果平台要求登录或验证码，停止并由管理员处理，不绕过限制。凭据只能由本机环境/现有凭据管理提供，不填在页面、授权依据、target 或命令行。程序不会安装依赖、修改 PATH 或下载脚本。默认 Python 未安装 aiotieba 时会返回 UNAVAILABLE。

只读契约根据 [aiotieba 客户端参考](https://aiotieba.cc/ref/client/)及其 [Threads](https://aiotieba.cc/ref/classdef/threads/)、[Posts](https://aiotieba.cc/ref/classdef/posts/)、[Comments](https://aiotieba.cc/ref/classdef/comments/)结构适配。启动时检查本地方法签名；只有真实调用及论坛标识检查成功才 READY。未知结构拒绝继续，不猜字段或合成 ID。

## 队列及证据

- 同一来源/tid 使用固定 fingerprint，标题、摘要、回复计数和最后回复时间只更新元数据。
- `material_queue.data` 保存楼层/回复版本、已提交分片哈希、扫描已见 ID、分页位置、原始读取片段、提取/验证缓存。无需新增 Schema。
- 每次读取一个独立楼层或楼中楼，文本按最多 2400 个 Unicode 字符分片，保留 pid/replyId/parentPid/floorNumber、页内 index 和 offset。长文本尚未读完不会标记 complete。
- 只有 publish 事务成功才提交已处理 ID 和下一游标。失败保持当前读取/提取/验证结果；重启重入队不会重置它们。
- 已完成帖在重新发现且至少经过 60 秒后可重新扫描。按稳定 pid/replyId 和正文哈希跳过历史内容，不产生 select/extract/verify 重复费用；新增回复和真实编辑才提取。扫描会产生有界只读请求，不保证零网络开销。
- 单轮发现最多 50 页，空页和重复页终止，使用现有来源刷新间隔等待下一轮。各来源通过原有最早尝试时间轮换。
- 空页/重复页导致的非权威扫描不推断删除。完整扫描中不再出现的 ID 标记 deleted；已编辑或已删除版本的证据保留在 SQLite 中，但不会参与聊天检索或候选补证。
- 旧版贴吧队列需要合并时先 VACUUM INTO 备份，再在事务中按 source/tid 保留最完整检查点及已提交片段集合。只归并贴吧 platform-reader 队列，历史知识、候选、证据、usage、documents 和其他平台数据保留。本机无贴吧历史材料时不执行该迁移。

知识仍通过统一 select → extract → validate → verify → publish 写入 `community.sqlite`。跨平台同词同义候选经既有审核合并补证；多义或冲突不自动批准。引用必须来自当前记录的原始文本，不能引用程序生成的层级标签。证据保留论坛、tid/pid/replyId、版本哈希和原帖链接，不保存作者账号资料。

## 管理及聊天

来源行显示独立状态、错误、重试时间、队列和知识数量，可分别启停/检查。学习日志使用原有 SQLite、分卷 JSONL 和增量接口，显示真实标题、tid、pid、replyId、页码、分片和模型用量。链接仅允许 `https://tieba.baidu.com/p/<真实数字tid>`；标题使用 textContent。

已发布知识直接进入 CommunityStore FTS、runtime 显式解释、StyleResolver 和 ExpressionRetrieval 主动表达。既有 fuseKnowledge 负责与原生黑话和 B站知识去重。既有许可、applyKnowledge、撤销、语境保护及每群独立表达使用记录继续生效。

## 定向验证

```powershell
node --test extensions/bigfatfish/community-tieba.test.mjs extensions/bigfatfish/community-platforms.test.mjs extensions/bigfatfish/community-learning.test.mjs extensions/bigfatfish/community-continuous.test.mjs extensions/bigfatfish/community-controls.test.mjs extensions/bigfatfish/community-evidence.test.mjs extensions/bigfatfish/community-conversion.test.mjs extensions/bigfatfish/community-video-dedup.test.mjs
```

platforms 测试会运行 `community-tieba.test.py` 的 22 个离线 aiotieba 契约测试。合成 worker 模式只在测试文件中，不会进入生产连接器。所有测试使用临时目录、模拟 DeepSeek usage 和合成帖子，不调用真实模型或 QQ 发送接口。

技术链路通过不等于真实论坛验收通过。必须另有有效环境、网络和内容许可，才可最少量执行实际 probe/discover/read；任何未验证的具体贴吧都不宣称存在或 READY。完成开发后持续学习保持 STOPPED，管理员自行开启。
