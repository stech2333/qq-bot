# V4.1 知乎定向学习

知乎复用 CommunityLearning、community.sqlite、候选/证据/FTS、DeepSeek select/extract/verify、StyleResolver 和 ExpressionRetrieval。没有新增数据库、模型服务或聊天检索流程，B站及贴吧驱动不变。

## 官方能力核实

直接读取了知乎官方文档页面使用的公开目录 `https://developer.zhihu.com/console/api/v3/docs`，不是根据第三方接口文档猜测。对接依据：

- [鉴权](https://developer.zhihu.com/docs?key=authorization)：Access Secret 的 Bearer 认证，秒级 X-Request-Timestamp。
- [知乎搜索](https://developer.zhihu.com/docs?key=zhihu_search)：GET `/api/v1/content/zhihu_search`，Query/Count，最多 10 条。ContentText 为摘要，HasMore 当前固定 false，没有可用的搜索翻页契约。

- [问题回答](https://developer.zhihu.com/docs?key=question_answers)：GET `/api/v1/content/question_answers`，QuestionUrl/Offset/Limit；返回回答摘要。Paging.IsEnd=false 必须使用 NextOffset，不能根据短页或空页推算结束。
- [我的创作全文](https://developer.zhihu.com/docs?key=user_content_detail)：GET `/api/v1/user/content_detail`，ContentUrl；仅当前 Access Secret 所属账号本人已发布内容。Body 可以包含 HTML。归属不符、不存在或不可用会失败。
- [我的创作评论](https://developer.zhihu.com/docs?key=user_content_comments)：GET `/api/v1/user/content_comments`，仅本人创作下的评论。根评论及附带 Children 有真实 ID；附带子评论不保证完整。
- [额度](https://developer.zhihu.com/docs?key=quota)：以账号实际开放额度为准，30001/30002 按限额处理，30003 按风控拒绝处理；不通过频繁重试或换接口绕过。
- [官方 CLI](https://developer.zhihu.com/docs?key=zhihu_cli)与 [官方 MCP](https://developer.zhihu.com/docs?key=unified_mcp)存在，但本模块直接使用上面的官方只读 HTTP 子集，没有自动安装 CLI、第三方 MCP 或发布工具。

实测官方搜索的 `ContentID` 可以与 `Url` 路径中的文章/回答 ID 不同。连接器将 `ContentID` 单独保留为 `searchContentId`，以白名单 HTTPS 原帖 URL 的真实 ID 建立材料身份和去重键；仍检查类型与 URL 一致，全文返回的 `ContentToken`、URL 和父问题必须匹配。搜索标识变化不会产生新材料，搜索摘要也不会作为全文学习。

官方当前没有向该学习器提供“任意作者全文”“精确话题内容列表”或“专栏文章列表”的已核实接口，因此这些目标不会被伪装为已接通。问题回答摘要也不会进入全文学习。

## 入口矩阵

| 目标 | 授权文件/Feed | 官方 HTTP | 已审核 readonly-json |
| --- | --- | --- | --- |
| keyword | 按精确 bindings 过滤 | 搜索摘要；只有实际本人全文读取通过才能 READY | 需声明并实际证明目标和正文能力 |
| topic exact | 按明确话题 bindings 过滤 | UNSUPPORTED_CAPABILITY | 必须实际支持精确话题 |
| topic keyword | 显式话题关键词绑定 | 按名称搜索，明确标注非精确订阅；正文仍限本人 | 必须说明对应能力 |
| question | 独立问题描述和回答材料，按 questionId 关联 | 任意回答全文学习不支持，仅有摘要接口 | 需实际问题/回答/正文支持 |
| answer | 只选指定 answerId | 仅本人已发布回答，服务端核验归属 | 只读指定回答 |
| article | 只选指定 articleId | 仅本人已发布文章 | 只读指定文章 |
| column | 明确专栏 bindings 的授权导入 | UNSUPPORTED_CAPABILITY | 需实际专栏列表能力 |

这张表描述代码能力，不代表本机已经获得所有在线权限。2026-10-30 本机已配置知乎官方连接器、Access Secret 引用和四个关键词来源，真实搜索已验证；任意作者全文及评论不在当前官方接口能力范围内，不能由搜索成功推断为全文学习成功。

## 管理页面

进入“记忆与学习 → 社区持续自主学习 → 授权来源管理 → 添加知乎目标”。

选择关键词、话题、问题、回答、文章或专栏。默认使用授权文件；填写文件名和目标，并记录真实的读取、保存和 AI 学习依据。一个目标一个来源，ID 登记后不能改变入口类型、目标、父问题或话题模式。只读权限、学习启停、历史知识应用分别管理。

关键词/话题 URL 会正规化；数字 ID 不经过会拒绝长数字的普通黑话文本校验。回答 URL 保留 questionId 和 answerId。话题名称不推断成唯一话题 ID。开启评论读取需要明确勾选评论选项；默认不读取评论。

“检查此来源”必须实际发现一条匹配材料并读取真实正文才 READY。导入成功标记 authorized-file/authorized-feed，页面明确说明不是在线搜索。没有匹配原文、只支持摘要、程序缺失、权限不足及不支持的入口分别报错。

原有 `/api/bigfatfish/community` 接口继续用于 source/probe/retry/start/stop。SQLite 和 JSONL 事件日志只含标题、原始链接、ID、类型、游标位置、计数、哈希和用量，不保存完整原文或模型回复。

## 官方连接器配置

在实际运行目录 `state/community-connectors.json` 的既有对象中增加以下项，保留 bilibili、tieba 等原项：

```json
"zhihu": {
  "platform": "zhihu",
  "driver": "zhihu-official",
  "credentialRef": "QQ_COMMUNITY_ZHIHU_ACCESS_SECRET",
  "minRequestMs": 3000
}
```

凭据仅通过现有进程环境变量或 DSH 凭据引用提供。API 根域名固定为 `https://developer.zhihu.com`，不能由网页或模型指定；仅允许四个已核实 GET 路径，不跟随重定向，不调用直答、个人收藏、关注、私信、统计画像或写接口。请求及响应有超时、取消和大小限制，Int64 ID 保持字符串精度。

不要把 Access Secret 放入源码、target、授权依据或普通导入文件。没有凭据时保持 NEEDS_AUTH，不能用修改数据库状态代替 probe。

## 授权文件及 Feed

文件放在桥接运行目录 `state/community-imports`，复用原路径、文件大小、Feed HTTPS 及取消保护。

以下是**合成结构示例，不是已读取的真实知乎材料**，不能据此声称真实学习成果：

```json
{
  "version": 1,
  "items": [
    {
      "id": "answer:456",
      "contentType": "answer",
      "questionId": "123",
      "answerId": "456",
      "title": "由授权导出提供的真实问题标题",
      "summary": "由授权导出提供的摘要",
      "url": "https://www.zhihu.com/question/123/answer/456",
      "publishedAt": 0,
      "text": "替换成获准保存和学习的完整原文。",
      "bindings": [
        { "type": "keyword", "value": "人工智能" },
        { "type": "topic", "value": "1955", "mode": "exact" }
      ],
      "comments": [
        { "id": "11", "text": "授权评论原文。" },
        { "id": "12", "parentId": "11", "rootId": "11", "text": "另一条独立评论原文。" }
      ]
    }
  ]
}
```

必须把示例 ID、URL、标题、原文及 bindings 替换成真实授权数据。发布时间未知使用 0，不补造时间。实际时间字段为 Unix 毫秒。作者昵称和账号资料不需要导入。

- 文章使用 `article:<id>`、contentType=article、articleId 及 `https://zhuanlan.zhihu.com/p/<id>`。
- 问题描述使用 `question:<id>`、contentType=question、questionId 及问题 URL，作为独立材料，不能拼接回答作者的观点。
- keyword/topic/column 来源只选择 bindings 明确匹配的材料；question 依据 questionId；answer/article 依据真实内容 ID。
- HTML 转换为安全的引用纯文本，删除脚本/样式，不执行 HTML，不用模型生成摘要替换正文。

## 已审核只读 JSON 连接器

仅供管理员已经核实并获准使用的本机只读程序。不会安装或套用未知第三方 CLI。

```json
"zhihu": {
  "platform": "zhihu",
  "driver": "readonly-json",
  "command": "D:\\实际已核实程序\\reader.exe",
  "args": [],
  "readOnly": true,
  "verified": true,
  "protocol": "bigfatfish-zhihu-v1",
  "minRequestMs": 3000
}
```

每次 stdin/stdout 交换一个 JSON，复用现有进程、凭据、超时和取消机制。请求固定包含 version=1、platform=zhihu、action、targetType、target、topicMode、readComments；仅允许 probe/discover/read。

- probe 响应：`{version:1, ready:true, capabilities:{targets:[...], body:true, comments:false}}`。能力声明还必须通过后续真实 discover 和 read 校验，不能仅靠声明 READY。
- discover 响应：`{version:1, items:[上述规范元数据], cursor:<JSON>, hasMore:boolean}`。items 不应携带正文；目标关联必须可校验。游标缺失、重复或不推进会停止。
- read 响应：`{version:1,id,url,text,contentType,records:[record],readCursor,complete}`。每次一条独立正文/评论分片，不合并发言者。record 含 document（规范材料 ID）、unitId（正文 ID 或 comment:<id>）、contentType、offset、end、version（完整该单元文本 SHA256）、contentHash（当前分片 SHA256）、text。评论还需真实 commentId，可带 parentId/rootId。
- 对正文不支持的目标返回 UNSUPPORTED_CAPABILITY，不把摘要冒充正文。未完整阅读必须返回后续游标，单次正文不超过 16000 个 JS 字符。

## 去重、恢复与证据

同一 source/content ID 固定 fingerprint；元数据、点赞和评论数不改变材料身份。回答跨关键词、话题和问题入口仍使用同一规范 answer ID。每个来源分别保存授权、队列、发现游标和阅读检查点。

每片最多 2000 个 Unicode 码点；包含 offset/end、完整单元版本及分片哈希。长文正文快照只在当前授权来源尚未读完时留在队列检查点，完成后释放。评论按稳定 ID 分开处理。已完成内容按原刷新节奏重新检查；正文变化只提取实际变化的分片，新评论不重学正文。

成功的提取结果及单片证据审核结论保存到 material_queue.data；不增加 Schema。跨来源复用前，当前来源必须实际读到相同片段，原来源仍有保存/学习/使用许可，来源 revision 和知识 generation 有效。候选再次经过本地 quote/schema/privacy 校验，仅复用同一片段、同一含义、同一引文的已审核结果。跨材料补证或冲突候选仍走原 verify 规则，不能凭缓存自动批准。

只有 publish 事务成功才推进游标和提交已处理哈希。DeepSeek 或数据库失败时保留原读取片段、提取及审核缓存。正文编辑后旧证据保留可追溯记录，但旧单元版本不参与聊天检索或补证；已撤销知识不因缓存重新发布。

当前许可证撤回、allowUse=false、知识撤销、有效期届满或 applyKnowledge=false，仍使用原有使用门控。暂停读取不自动删除历史知识。B站、贴吧与知乎同词同义经原 verify 和 publish 规则合并补证，多义与矛盾不会自动合并。聊天场景仍由既有检索和 StyleResolver/ExpressionRetrieval 决定，认真求助不强制用梗。
