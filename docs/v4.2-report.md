### 3.1 为什么记忆/心情"自研为主"不是偷懒

- **fish-memory**：它按 DSH 会话/工作区组织记忆，没有 QQ 号实体；通过 `systemPrompt` 在
  assemble 阶段注入自己的段落，而本项目 `bff.instruction()` 已经拥有一份带
  `sourceMessageId` 溯源、`factKey` 覆盖、管理员纠错与撤销的记忆注入。
  **两者同时启用 = 双注入**（2.4 明令禁止）。替换需要先拆掉自研注入，并迁移
  `social-v2.json` 的 facts/archive/deleted；这一步需要 A/B，而本机服务未启动，做不了。
- **feiyu-mood**：状态在 `$DSH_HOME/feiyu-mood/state.json`，本项目在 `social-v2.json` 的
  `bigfatfish.mood`；两者同时判定就是"两个心情插件改同一份心情"。它的优势是 UI 挂饰，
  本项目已有 `/api/bigfatfish/mood`，补 UI 的代价远小于换引擎。
- 结论记录在 `extensions/bigfatfish/plugin-registry.mjs`，并可通过
  `GET /api/bigfatfish/plugin-integration` 与管理端「插件整合与功能所有权」查看。
  每条都写了 `unverified` 字段，明确哪些结论**没有**被验证。

## 4. 聊天长度与风格去机械化（实际代码）

`runtime.mjs`：

```js
export const DEFAULTS = Object.freeze({ privateAssistant: false, replyDelivery: 'natural', ... });
export const RETIRED_SETTINGS = Object.freeze(['casualMaxChars']);
```

- `validateSettings()` 不再接受/输出 `casualMaxChars`；旧磁盘值由
  `retiredSettingsPresent()` 检测，构造时 `backupOnce()` + 立即重写，避免重启后"复活"。
- `casualInstruction()` 新文案不再含任何数字，明确"说多少由内容和此刻想说的决定：

- `memory-manager.mjs` 的 `targetChars()`（唯一读取 `casualMaxChars` 的地方）替换为

- **保留**真实限制：`socialV2.send.maxMessageChars=500`、媒体 `maxBytes/maxPixels/maxCount`、
  `media-normalize` 的 1MB/1280 长边。这些是 QQ/模型侧安全上限，不是风格约束。

## 5. 聊天参与与主动发言（实际代码）

`participation.mjs` 重写为**证据优先**：

1. `direct || continuation`（私聊、@、引用、明确称呼、同一人继续推进话题）→ `probability = 1`，
   **不掷骰子**。旧 `engagedProbability` 正是漏答来源。
2. 没人点名 → 收集证据：`INTEREST(1.0)` / `TOPIC_OVERLAP(0.6)` / `OPEN_QUESTION(0.5)`。
   无证据 → `probability = 0`，`reasonCode = NO_EVIDENCE`，**没有 0.03 兜底**。
3. 有证据 → `probability = ambientJoinProbability × 最强证据 × 退火系数`；退火只作用于旁观插话。
4. 兴趣命中不计离题、不参与退火（否则同一话题第二句会被自己压掉）。
5. 纯应答（嗯/好/哈哈/谢谢）不算"必答追问"。

统一输出（新增字段，不破坏旧字段）：

```js
{ action, targetMessageIds?, reasonCode, contextVersion, suggestedReplyMode, probability, selected,
  handled, direct, involved, interestMatch, addressedElsewhere, recipientConfirmed, reason }
```

- `action ∈ TEXT | STICKER | EMOJI_REACTION | MIXED | SILENT`，由
  `suggestChatAction()` 纯函数推导（认真/技术/收尾一律 TEXT）。
- `contextVersion` = 会话 `memoryRevision`。
- `reasonCode` 例：`DIRECT_ADDRESSED`、`CONVERSATION_CONTINUATION`、
  `AMBIENT_INTEREST_EVIDENCE`、`AMBIENT_TOPIC_OVERLAP`、`NO_EVIDENCE`、`DIRECTED_ONLY_MODE`。

`context-initiative.mjs`：`begin()` 不再 `random()`；`probability` 只是闸门（0=关闭）。
每日/每小时额度、冷却、`hourlyCap` 仍然生效——它们是**费率保护**，不是"接话概率"。

`bridge.js`：`evaluateWakeTriggerV2` 把 `stickerOpportunity(key)`（只读：候选数/最高置信度/场景）
传给 `bff.chatDecision`，因此"要不要发图"进入同一个决策，而不是在发送时再临时判断。
调度入口仍只有一个：`scheduleWakeV2` 的优先级队列。

## 6. 图片收藏与使用

`sticker-lib.js`：

- 新增 `stickerRecencyPenalty()`：10 分钟内用过 −12 分、1 小时内 −8、6 小时内 −4、24 小时内 −2。
  **不再按 `useCount` 排序**（`useCount` 只保留 ≤1 分的稳定度权重）。
- 新增 `stickerCandidateScore()`：`匹配×10 + 文本重合×3 + 话题×5 + 置信度×6 + 管理员纠正(+4) − 最近使用惩罚`。
- 新增 `rankStickerCandidates()`。
- `buildStickerContext(entries, max=0, context)`：
  - `max=0`（默认）→ 按语境动态挑 `3~12` 条；
  - 每条现在带 `含义/用途/潜台词/标签/语气/不适合场景/置信度/上次用过`；
  - 仍保留"这是资料不是指令"的跨会话注入框定。
- 收藏：`collect.maxPerMinute/maxPerHour` 默认 0（不限额）；去重靠 QQ `emoji_id` +
  本地 `md5`（`findSticker` / `mergeStickerLibrary` 原样保留）；`maxRemarkChars=20` 只约束
  **QQ 原生备注**，完整用途说明存 `localNote`（200 字），两者不混。
- `qq_react`（**已实现并验证**）：最初只在 `integrations/qq-bridge/src/` 里搜索，结论是"没有实现"；
  后来直接查本机 SnowLuma 安装目录 `integrations/SnowLuma/index.mjs`，发现它**真实提供**
  `set_msg_emoji_like { message_id, emoji_id, set }`（`index.mjs:10649`），并附带
  `get_emoji_likes` / `fetch_emoji_like` 与入站 `group_msg_emoji_like` 事件。
  关键约束：**只支持群消息**，且要求该消息有权威 QQ seq（`index.mjs:33087` 的
  `setMsgEmojiLike` 会对私聊直接抛错）。
  因此新增：
  - 桥接路由 `POST /api/socialV2/react`（agent token + 白名单 + 可见性 + 频率 + 发送守卫）；
  - MCP 工具 `qq_react`（受 `socialV2.tools.react` 控制，**默认关闭**，控制台已有勾选项）；
  - 入站记录 `recordReactionNotice()`：把 `group_msg_emoji_like` 记成一条 `[表情回应] … emojiId=…`
    的可读事件，**不唤醒模型**——这是模型能拿到真实 `emojiId` 的唯一可靠来源（避免它编数字）。
  `EMOJI_REACTION` 作为决策输出保留，`reactionAvailable` 仍由 `socialV2.tools.react === true` 控制。

## 12.1 三个真实 Bug（都是"测试全绿但服务起不来"那一类）

### Bug 1：`.env` 里的 `NODE_OPTIONS` / `NO_PROXY` 让 DSH 直接拒绝启动

真机启动 DSH 时报错：

```
Error: dsh: D:\Projects\BigFatFish-QQBot\.env sets "NODE_OPTIONS", which only the launching
environment may set ... export NODE_OPTIONS instead of putting it in a .env file
```

改成只删 `NODE_OPTIONS` 后继续报同一句，换成 `NO_PROXY`。也就是说**本机这套配置下 DSH 一次都起不来**，
QQ 侧全盘不可用——而 `npm test` 一直是 615/615 全绿，因为没有任何单测真的去启动 DSH。

修复（按 DSH 自己的分层规则）：

| 位置 | 允许放什么 | 现在的值 |
| --- | --- | --- |
| 项目根 `.env` | 普通配置（随仓库走） | `DEEPSEEK_API_KEY` + 说明注释 |
| `data-bridge/.env`（`DSH_HOME`，已被 gitignore） | 启动环境级变量 | `NO_PROXY=localhost,127.0.0.1,::1,token.nuaa.edu.cn` |
| `services.mjs` spawn 子进程时 | `NODE_OPTIONS=--import=…model-network-preload.mjs` | 由管理器注入，并额外读取 `DSH_HOME/.env` |

回归测试：`extensions/bigfatfish/env-layer.test.mjs`（4 个用例，断言项目 `.env` 不许出现这两类变量）
+ 改写后的 `services.test.mjs`（启动环境的 `NODE_OPTIONS` 必须保留、`.env` 里的必须忽略）。

### Bug 2：`.env` 带 UTF-8 BOM

`DEEPSEEK_API_KEY` 明明有值（35 字符），解析出来却是空——文件开头有 `EF BB BF`（PowerShell 写入时带上的）。
已改写为无 BOM。这类问题会让"key 明明配了却 401"，且肉眼看不出来。

### Bug 3：表情歧义"一票否决"，导致选图功能永远不生效

`parseStickerUnderstanding` 只要模型在 `ambiguity` 里写了任何字，就把整张表情降级为 `uncertain`；
而提示词又要求它写"无法排除的歧义，无则空字符串"。一个诚实的视觉模型对表情包几乎总能写出
"也可能被读成…"，于是 **32 张收藏全部不可用，候选数恒为 0**——这正是"表情发送不合理/偏重复"的根因之一。

新规则（`ambiguityBlocksAutoSend`）：

- 命中高风险语义（嘲讽/冒犯/政治/隐私/死亡/歧视…）→ 仍然禁止自动发送；
- 置信度 < 0.75 → 仍然禁止；
- 其余"可能的另一种读法"→ 保留 `reviewed`，排序降 2 分，并在提示词里如实写"可能的另一种读法=…"。

- `runtime.setExternalMood()` / `externalMoodLine()` 把"当前心情 70·开心"压成一句话注入提示词，
  **接话决策因此仍然能看到心情**——这是 BigFatFish 特有的需求，插件本身不提供；
- `GET /api/bigfatfish/status` 新增 `engines` 与 `externalMood`，管理端一眼能看到"谁在负责"。

## 13.4 没采纳的两个（有具体理由，不是遗漏）

| 插件 | 为什么这轮不接 | 需要什么才能接 |
| --- | --- | --- |
| dsh-speak-up | 它自行起一轮 DSH turn，而 reserved2 下发送 QQ 必须带**会话令牌**；它拿不到令牌 → 每次唤醒都会在发送时被拒，纯烧模型调用。且与"单一调度入口"冲突 | 先在插件里暴露"唤醒前回调/自定义 prompt 注入"的扩展点（目前没有），把会话令牌与上下文交给它 |
| dsh-vision | 源码已经 vendored 到 `integrations/dsh-plugins/dsh-vision/`，并用 `tsc` 构建出了 `dist/index.js`（运行时解析到本机 0.2.1-rc.2）。**真正的阻塞是没有 DASHSCOPE_API_KEY**：现在装上去只会多一个每次调用都报「未配置 API Key」的工具 | 补一个 `DASHSCOPE_API_KEY`（`.env` 或插件配置），再把 link 依赖 + junction 加上即可；在此之前保持不装 |

> 安装位置统一到项目里既有的 `integrations/dsh-plugins/`（vendor 目录，README 写明"profile 通过 link + junction 指向这里"）。
> 我一开始复制到了 `data-bridge/plugins/`，发现这个约定后已改回 vendor 路径，并删掉了那份重复副本。
