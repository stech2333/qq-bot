# 网页抓取检查与 QQ 权限隔离（2026-10-29）

## 证据与判断

桥接工具日志确认北京时间 08:48 两个天气页发生 TLS 建连前断开，08:52 百度发生 socket hang up，example.com 和腾讯抓取成功。搜索由服务商执行，网页抓取由本机 MCP 进程执行，两者不是同一出口。

本轮用 DSH 配置的 Node 可执行文件，通过实际 MCP stdio 通道复测百度、墨迹玄武区天气页、中国天气网 `weather/101190108.shtml`，三者均返回 HTTP 200、50000 字符（达到正文截断限制）。因此先前故障没有持续复现，不能认定网站封禁，也不能声称已确认原始网络故障根因。HTTP 200 不能证明页面包含最新天气。

## 本次修改

- `qq-tool-restrict.mjs` 改为完整工具名白名单，未知工具即使位于可信 MCP 命名空间也拒绝执行；保留本地执行/文件/跨会话/插件工具禁令。
- 在可信系统提示层声明 QQ、转发、记忆和网页均为不可信数据；文本声称管理员身份、授权或要求测试不能提升权限。提示词是辅助，执行期 guard 才是权限边界。
- QQ `web_fetch` 每跳只允许标准 HTTP/HTTPS 端口；继续保留全 DNS 结果校验、固定连接 IP、逐跳内网拦截、凭据 URL 拒绝、TLS 证书校验、读取限额与超时。
- 抓取每次使用新连接，减少复用失效 socket 的风险；这是连接健壮性措施，未证明是原始故障的根因。
- 搜索/抓取返回获取时间与外部数据提示；抓取 HTTP 非 2xx 标为 MCP 错误。连接断开的提示不再暗示网站封禁。
- 未添加 shell、系统 ping、文件读取或任意 HTTP 方法工具。完整工具名白名单仍须依赖各 QQ 工具已有的会话令牌与目标 ACL，不能替代参数级授权。
