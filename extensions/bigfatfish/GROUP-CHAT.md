# 群聊对象确认与自然回复

管理端“兴趣与主动策略 → 接话与退火”可开启“群聊确认在跟机器人说话才回答”，并关闭“群聊允许引用原消息”。这两个开关独立于接话概率。

开启对象确认后，真实 @机器人、回复机器人的消息、直接称呼机器人，或当前聊天对象尚未被其他对话打断的连贯追问，才能进入回答判断。@别人、引用别人、第三人称谈到机器人、陌生人的泛泛问题、单纯话题重合或兴趣命中都不足以确认对象。对象不明时先旁观，概率和关键词不能越过这项限制。

每条来信保留对象判断；模型在读取新消息或等待消息时会得到当前待答消息 ID 和表达要求。发送端也检查是否存在已确认的待答消息，防止正在运行的旧回合抢答。已开始的一批回答可完整发完；后续消息转向他人后，新的发送调用会重新检查。

关闭群聊引用后，文字和收藏表情在网关发送前会去掉 QQ 引用段，但保留内部回复目标和已读进度。私聊引用不受该群聊设置影响。

只有平台真实 @机器人的消息采用正式、完整回答，不受闲聊字数目标限制。正式风格只作用于对应 @消息的答案；同批普通话题以及未 @的后续聊天恢复当前角色卡原本的口吻、个性和说话习惯。私聊、称呼名字和回复机器人本身不触发正式模式，旧的“私聊详细回答”设置也不再生效。

正式回答保留当前角色的用词、态度和表达方式；@提高回应优先级，不代表统一改成助手口吻。只有需要讲解的问题才按需展开，简单问候或感慨不自动扩写成建议、评价和人生道理。自主表达也不要求每轮必须发表观点：有具体内容才延伸，避免先认同再说理、重复改写同一个意思和对仗金句。

普通聊天默认每条消息约5–25字，一条说不完可按完整语意分成多条回答，总字数不受单条目标限制；每条说清一个意思，不拆碎短句。直接接话、不复读原话、少用客服开场与无必要的总结，意思说完后停下来。长度在生成时控制，发送端不截断句子、英文标题或链接。当前角色卡继续生效，长期记忆只轻微影响语气，不覆盖角色风格和字数目标。

日常接话也要贡献自己的内容：合并理解同一话题的消息，承接后主动分享一个观点、联想或具体细节，可以顺势展开相关角度，少用纯附和，不固定以反问收尾。素材来自当前角色设定、本会话相关长期记忆、共同讨论的话题与预设，读取消息和持续等待时都会刷新。真人明确提出的聊天偏好可按现有记忆机制学习；关闭个性化后不提供记忆素材。不要把他人的偏好说成自己的真实经历，没有回应时自然收尾。
