# 接话、持续参与与退火

普通群聊采用会话独立的接话状态，不再只依赖固定随机概率。

- 被真实@、引用、叫昵称，以及明确针对机器人的问题：必定触发查看，提示模型优先及时回应；不提升工具权限。私聊同样及时处理。
- 当前部署普通旁观40%触发，命中已学话题的接话概率下限60%。成功发言后进入参与状态。
- 最近两分钟内，同一聊天者的相关追问、承接语、表情，以及其他人对当前话题的延续：当前部署60%触发接话。
- 不再涉及它时进入退火：每两条无关消息、或每90秒，参与热度减半。明确@别人或引用别人时冷却更快。最多8条无关消息或5分钟无相关互动后退出，降至3%。机器人自己的发言不会把退火重新拉满；重新找它则立即恢复参与。
- 中文话题承接使用关键词和有限的承接语规则，不额外调用模型做分类；含糊的人称和突然转换话题存在识别误差。模型仍需结合真实上下文，不能把触发概率理解为强制回复率。

直接找它及追问的合并等待为500毫秒，旁观候选为1.5秒；慢批次里新收到直接找它的消息时，会升级并提前批次。明确问题的可选短静默等待缩短至约2秒；明显没说完的句子仍给补充时间。模型生成、工具和网络耗时另计，不能承诺500毫秒内发出回复。

当前部署唤醒上限提高为每分钟6次、每小时60次；原有会话忙碌合并、出站额度、隐私审计和白名单继续生效。没有启用冷场主动开场：`coldStart.dryRun=true` 只表示无人聊天时的主动开场演练，普通消息的回应不受此演练开关限制。

「大肥鱼设置 → 人格与行为 → 接话与退火」可调概率、退火和延迟。状态保存在每个会话的 `bigfatfish.participation`，只包含时间、参与者ID、有限话题片段和最近判断，不与其他会话共享，也不写入长期人格或事实记忆。

## 聊天中随机主动（2026-10-25）

二代群聊新增 `contextInitiative`，由管理页开启；本机部署概率18%，冷却5分钟，参考最近10分钟上下文。它只在没有正常回复被选中、没有明确待答消息且有至少两条有效近期真人消息时，尝试分享一个相关观点、联想或小话题。明确找自己、私聊和正常回复不走此抽签。原40%/60%接话规则保留；新增机会会增加整体参与次数，不能把全部发言频率理解成固定18%。

概率在合并窗口结束后抽取一次，未命中也保存批次指纹，重启或重复调度不会为同一批消息反复抽签。普通回复和引导唤醒的优先级均高于随机主动。繁忙、离线、静默、暂停、限频时直接放弃随机机会，不进入繁忙后的补发队列；残留的旧随机唤醒也不会重放。

命中后先预占共用主动推理额度，发送成功后按一次主动轮次计费，多条短消息不重复扣该额度。沿用现有主动小时、全局每日和推理上限；默认共享静默23:00–08:00。`coldStart.dryRun`、冷场45分钟门槛和冷场每日次数不控制这项新功能。没有合适内容时模型仍可安静，18%是生成机会，不是无条件强制发送。

队列职责：

| 数据 | 含义与更新时机 |
| --- | --- |
| `unread` | 待处理真人消息；模型查看不会自动消费 |
| `modelSeenSeqs` / 可见游标 | 冻结本次发送前模型实际看到的消息范围 |
| `lastReadThroughSeq` | 已处理游标；可包含明确跳过，不等于每条都回答 |
| 最近 `isSelf` 记录与发送成功回调 | 已实际发送的消息记录，不能把已读当成已发送 |
| `pendingWakeTimer` / `pendingWakeReasons` | 共享合并及正常回复调度；不为随机主动另建发信通道 |
| `bigfatfish.contextInitiative` | 批次指纹、最近尝试和两分钟有效期的主动令牌，不保存另一份聊天队列 |

发送途中到达的新问题仍留在待处理队列。QQ发送失败不消费待答消息；分条发送部分成功时只确认原可见范围。主动回合调用“标记已读”或关闭时清理未读，也只能确认原批次水位，不能清掉随后到达的新问题。随机消息生成期间上下文水位变化、出现明确待答消息、停用会话或设置改变时，发送前再次检查并阻止旧主动内容；已取消/过期的主动令牌不能用于迟到的模型请求。QQ已成功发送后的主动账本失败只暂停后续随机主动，不把成功消息改报为发送失败，避免重试造成重复。

管理页“话题与主动策略”显示各会话待处理数、明确待答数、处理游标、近期已发记录数和随机主动阶段。这些是有界近期状态，不是永久消息审计库。
